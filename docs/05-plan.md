# esp32-buddy-touch154：开发计划（阶段 2）

> 日期：2026-10-30；版本：v0.1（阶段 2 草案，待 DoR）
> 风险优先，**不是瀑布**。每个 `M` 都是**纵向可演示增量**。
> 第一版范围由 `Q03` 批准：显示 + 2 应用键 + 3 卡 + 番茄钟 + 语音播报。

## M1：1.54 板点亮 + 240×240 出正确一帧

- **用户价值**：插上电，屏幕上出现宠物；证明屏、背光、电源锁存、板级层都对
- **入口**：`Q02/Q03/Q05/Q06` 已批准；`C01/C02/C06` 冻结；IDF 可用
- **交付**：
  1. `firmware/` ESP-IDF 工程骨架（target esp32s3，16 MB flash，octal PSRAM）
  2. `board/` 板级层：I2C、电源锁存（GPIO2）、背光（GPIO46）、ST7789 240×240
  3. `pet_render` 在 240×240 上渲染 **IDLE 一帧** + `READY` 文本
  4. host 端 BMP 预览（同一渲染代码）
- **测试策略**：**T**（渲染边界/透明像素/坐标，host 可跑）+ **H**（真机目视 1 帧）
- **适用用例**：`LCD-01`（240×240 满屏无偏移）、`LCD-02`（反色正确）、`PWR-01`（GPIO2 拉高保持供电）、`UI-01`（一帧可辨）
- **演示脚本**：`idf.py flash` → 屏幕出现宠物 + `READY`；按复位仍出现
- **失败场景**：面板初始化失败 → 日志明确、不挂死；背光不亮 → 仍能通过串口看到启动日志
- **前置实测**：出厂日志已确认 SPI 总线、背光、CST816、ES8311、ES7210、QMI8658、RTC 均应答；M1 只需确认 **SPI mode / 反色 / gap**（`B07`）
- **安全前置**：首次刷写前必须全片备份出厂固件并记 sha256（`B17`）
- **出口判据**：✅ **M1 通过（2026-10-30）**：真机目视「宠物+READY、颜色正常、居中完整」（E14）；`LCD-01/02`、`UI-01` 通过；`PWR-01` 仅日志+USB 供电，电池保持未单独验
- **明确未交付**：动画、任务卡、番茄钟、按键交互、语音、WiFi/BLE、触摸、IMU
- **不算完成**：只有 host BMP 预览；或屏幕亮但内容错位/反色错误

## M2：6 态动画 + 3 卡栈（240×240）

- **用户价值**：宠物随 Agent 状态动起来，能同时看 3 个任务
- **入口**：M1 出口；`C03` 版式冻结（2026-10-31 增 §7 修订 R1–R8）
- **进度**：✅ **已交付（2026-10-31）**：实现 + 真机证据 `E16`（T）、`E17`（G1）、`E18`（G3）、`E19`（MEM-01）；交付说明见 `09-m2-delivery.md`
- **交付**（已实现）：`pet_state`（6 态/done 边沿去抖/DONE 驻留/失联/眨眼与 12 帧相位/3 卡栈）、`pet_ui_240`（状态条/宠物/居中标记/3 卡/离线灰化）、8 fps 主循环、串口注入 + 帧缓冲导出（M2 调试用）、host T 测试 15 用例/231 断言、`tools/host` 跑测工具
- **测试策略**：**T**（状态转移、done 边沿去抖、卡片置顶/淘汰、像素版式）+ **H+T**（真机帧缓冲导出 + 像素断言）；人眼 H 待用户确认
- **适用用例**：`ST-01..09`、`UI-10/11/12/13`、`CARD-10..15`、`GB-01`、`FRM-01`、`MEM-01`
- **演示脚本**：复位后串口单字符注入 6 态 → 目视切换；`c`×4 → 置顶/淘汰；`tools/host/run_g1.py`、`run_g3.py` 自动跑
- **出口判据**：`G1` **24/24**（偏差已登记：分母原文 20）、`G3` **20/20**、`MEM-01` PASS
- **明确未交付**：番茄钟、菜单、按键、语音、网络；`FRM-01` 撕裂/闪烁未人眼验证
- **不算完成**：静态轮播冒充状态驱动（未发生：状态由 `pet_state` 驱动，G1 24 次注入可复现）
- **缺陷**：`D-05` 标记点阵镜像，真机发现并修复（回归 `UI-11b`）；`D-02` 误报已关闭

## M3：2 应用键 + 菜单 + 番茄钟

- **用户价值**：不用宿主也能开始/暂停/放弃番茄钟，能静音、看状态
- **入口**：M2 出口；`C07` 按键映射冻结（2026-10-31）
- **进度**：✅ **已实现并交付（2026-10-31）**：T 21/21 用例、G5 17/17、G6 260/260；**真机按压 H（KEY-01/02/05）待用户**（`E26`，用户选择先提交）
- **交付**（已实现）：`pet_button`（20 ms 采样 / 600 ms 长按）接入 GPIO0/4；`pet_keymap`；5 项菜单（MUTE/STATUS/WIFI(M5)/BT(M5)/BACK）；25/5 番茄钟 + 圆环 + NVS 统计；`PWR` 长按关机流程；`voice/muted` 持久化
- **测试策略**：**T**（长短按状态机、计时、跨日、菜单、像素）+ **H+T**（合成键 260 次、真机帧缓冲导出）
- **适用用例**：`BTN-01..03`、`KEY-01..05`、`KEYMAP-01..08`、`MENU-01..05`、`POMO-01..07`、`UI-20/21`、`G5/G6`
- **演示脚本**：KEY2 进番茄钟 → KEY1 开始/暂停/继续 → 长按放弃；PWR 长按关机
- **出口判据**：`G5` 4/4 + 重启 1/1 **17/17 PASS**；`G6` 每项 ≥19/20 **260/260 PASS**（合成键）
- **明确未交付**：真机按压计数 `KEY-01/02/05`（PENDING）、触摸、IMU、语音输入
- **不算完成**：只测短按（未发生：短/长/菜单/番茄钟均测）；统计只在内存（未发生：NVS 已验证重启持久）
- **缺陷**：`D-06`（番茄钟页 3 处渲染偏差）测试发现并修复；`D-03` 部分修复（时间源 M5）

## M5a：DSH 插件与 USB 事件入口（**2026-10-31 新增关键节点，优先于 M4**）

> 触发：用户 2026-10-31 明确"接入对象是 deepseek harness，最终要打包成符合 DSH 插件标准的格式。
> 这是项目的新增关键部分"。→ 宿主桥从"自研 Python 桥"改为 **DSH bundle 插件**；`Q04` 已批准；
> 节点顺序调整为 `M3 → M5a → M4 → M5b → M6`（M5a 是设备与 DSH 的接入主干，优先验证）。

- **用户价值**：真实 DSH 会话（任务开始/等待确认/完成/出错/空闲）驱动桌面宠物；装一次插件即接入
- **入口**：M3 出口；`Q04` 已批准（2026-10-31：DSH 插件）；`C05` 协议冻结（2026-10-31）
- **进度**：✅ **已交付（2026-10-31）**：设备侧事件入口+C05 解析（29/436 断言 PASS）、插件包 `host-plugin/`（56/56 + 安装验证）、设备 H **16/16**、**真实 DSH 会话 E2E 用户目视 PASS**（`E30/E31/E32/E33/E34`）。见 `13-m5a-delivery.md`
- **交付**：
  1. 设备侧：USB-Serial-JTAG **NDJSON 事件入口**（C05：6 事件 + `tasks` 3 卡 + 心跳；非法输入不崩）
  2. 宿主侧：**`host-plugin/` DSH bundle**（`dsh-esp32-touch-bridge`；`apply(ctx)` 订阅
     `session/created|disposed`、`session/event`（title/approval）、`agent/status|error`、
     `user-questions/request`；归约为 C05 行；经 PowerShell 串口 helper 写设备）
  3. 安装通路：`dsh plugin --profile desktop add <host-plugin>`；插件管理器可见/可停用
  4. 端到端：真实 DSH 会话 → 设备 ≤1 s 变状态/出卡；停止会话 → OFFLINE → 恢复
- **测试策略**：**T**（设备侧 linebuf/parser；插件 state/protocol reducer）+ **C**（C05 契约测试、
  插件装配 fake ctx/transport、临时 profile 安装）+ **H**（真实设备 + 真实 DSH 会话）
- **适用用例**：`E2E-01`、`C05-01..08`、`PLG-01..06`、`G2/G4/G12（USB 通道）`
- **出口判据**：设备解析 T/C 全绿；插件 `node --test` 全绿；临时 profile 安装 + `--dump-config`
  可见插件行；真机事件入口 H；真实 DSH 会话 E2E（需用户重启 DSH 后）
- **明确未交付**：WiFi/BLE 通道、配网、NTP（M5b）；语音（M4）；跨通道去重（M5b）
- **不算完成**：只有单元测试/模拟设备；插件装不上或真实 DSH 会话驱动不了设备

## M4：语音播报（ES8311 输出）

> 顺序说明：M5a（DSH 插件接入）优先；本节点在 M5a 出口后开工。

- **用户价值**：需要确认/完成/失败时出声；静音后重启仍静音
- **入口**：M3 出口；`C04` 音频输出契约冻结（2026-10-31 已冻结）
- **进度**：✅ **已交付（2026-10-31）**：C04 冻结、board_audio/ES8311/资产/静音门控、T 28/28、构建 0 warning、**H 听感用户确认"都正确"**（`E37/E38`）；`G9` 正式 60/60 留到发布前
- **交付**：ES8311 @0x18 + I2S（GPIO8/9/10/12）+ PA（GPIO7）播放 3 条 PCM；静音持久化
- **测试策略**：**T**（触发时机/去重/静音）+ **H**（实机听到）
- **适用用例**：`AUD-01…`、`G9`
- **演示脚本**：注入 input/done/failed → 各响一次；静音 → 20 次无声；重启 → 仍静音
- **出口判据**：`G9` 60/60 + 静音 20/20
- **明确未交付**：麦克风、语音输入、AEC
- **不算完成**：只有 `AUDIO QUEUED` 日志却没真响
