## 1. 目标与可行性结论（拟定）

在 **ESP32-S3-Touch-LCD-1.54** 上做一个"AI 编码 Agent 桌面宠物"：240×240 竖屏、触摸、3 键、双麦 + ES8311、6 轴 IMU、8 MB PSRAM、16 MB Flash。
技术路线建议以 **MIT 的 `ESP32-buddy` 固件**为基线（`Q02` 方案 A），保留其已验收的状态机/协议/宿主链，重写板级层与版式，并按 vibebuddy 的**设计**补触摸交互、卡片分页与 OTA。

可行性结论（阶段 0 证据支持）：
- **成立**：状态机、任务卡、番茄钟、休闲、事件协议、WiFi/BLE 传输、宿主桥——已有 MIT 实现，可复用。
- **需重做**：240×240 版式、ES7210 采集路径、板级电源/电池、按键语义。
- **全新**：CST816S 触摸、QMI8658 IMU、OTA、AEC。
- **硬前提**：必须解决 `B01`（型号确认）、`B02`（工具链）、`B03`（实机通路）。三者不解决，本项目只能停留在文档阶段。

## 3. 拟定需求（待审阅）

> 以下全部是**工程提案**，不是用户已批准的内容。带 🔴 的项会改变产品形态，必须用户拍板。

### 3.1 产品行为

| 编号 | 拟定要求 |
| --- | --- |
| `R10` | **240×240 竖屏专属版式**：宠物 + 任务卡 + 状态区；不复用 135×240 坐标；小屏信息不足时允许分页，不允许压缩到不可读 |
| `R11` | **6 态宠物**（IDLE / WORKING / INPUT_REQUIRED / DONE / FAILED / OFFLINE）可目视区分；OFFLINE 不得渲染成 IDLE |
| `R12` | **任务卡 ≤3 张**，最新在最上；每卡显示 Agent 前缀、会话名、项目、驻留时长；同名任务更新置顶 |
| `R13` | **番茄钟** 25+5：开始/暂停/继续/放弃；当日完成数与专注时长持久化，重启不丢；跨日清零 |
| `R14` | **休闲模式**：空闲 5 分钟演小剧、30 分钟犯困、夜间 90 分钟关背光；任何按键/触摸/事件/抬腕唤醒并重置空闲 |
| `R15` | **语音播报**：需要确认 / 完成 / 失败各播一次；WORKING 期间静默；静音开关生效且**持久化**（修正上游"重启恢复有声"） |
| `R16` | **按住说话（v1 后置，依赖宿主 `Q04`）**：按下开始录音、松开上传；最短时长不足则丢弃并提示；超时硬停；结果文本上屏并可"发送"到宿主 |
| `R17` | **按键**：三键可用；`PWR` 保留系统电源语义（长按关机），**默认不分配应用功能**；其余两键可完成全部核心操作 |
| `R18` | **触摸 🔴（v1 后置）**：点任务卡 = 查看/切换；竖滑 = 翻页；长按 = 打开菜单；"摸头" = 宠物反馈。触摸是**增强**，不是唯一入口 |
| `R19` | **IMU 🔴（v1 后置）**：抬起唤醒屏幕；摇晃 = 静音/确认（待定）。**不做**姿态识别、不做计步、不做屏幕自动旋转 |
| `R20` | **AEC 🔴（v1 后置）**：使用 ES7210 双麦 + ESP-SR AFE 实现"边播边听"（播报时可打断/继续说话）；降级路径为现有半双工 PTT |
| `R21` | **事件入口**：本机任意程序可发事件；USB、WiFi TCP、BLE 三通道；跨通道去重；非法输入不崩溃、不误改状态 |
| `R22` | **配网**：无凭据或菜单触发 → 热点网页选网；失败约 2 分钟回落热点；凭据持久化 |
| `R23` | **时间**：WiFi/NTP 授时；无网络时夜间规则降级为"不关背光"并明确提示，不猜测时间。板上实测存在 PCF85063A，但 **v1 不依赖它**（`B18`：与原理图冲突，地址/备份电池未验） |
| `R24` | **电池**：ADC 读取电量、充电状态显示；低电提示；**GPIO2 电源锁存在启动早期拉高** |
| `R25` | **OTA 🔴（v1 后置）**：双槽 + 校验 + 回滚确认；升级失败保留可启动旧版本；OTA 需用户显式触发 |
| `R26` | **分层**：状态/渲染/协议为纯逻辑，可在主机单测；**只有 board 层碰硬件**；修正上游"HAL 是唯一硬件层"名不副实的问题 |
| `R27` | **不复制 GPL 代码**：vibebuddy 只借鉴设计与协议；不得引入其源文件、素材或角色 |
| `R28` | **不使用 "VibeBuddy" 名称与角色商标**；设备名、AP 前缀、BLE 名使用本项目命名 |

### 3.2 明确禁止（写进需求，不是补充说明）

- 不把"读不到的状态"渲染成 `0`、`空闲` 或"已完成"。
- 不自动提交、不自动审批 Agent 动作；语音只做"填入/发送"，最终动作由用户触发。
- 不在未授权时刷机、发布 Release、创建公开仓库。
- 不以降低门槛的方式让验收"变绿"（删失败用例、放宽断言、改口径）。
- 不在 `PWR` 长按关机路径上做应用层拦截。

## 4. 验收门槛（G）

> 门槛承载数值与判定标准；需求只写意图。**分母不剔除**，失败样本保留。

| 门槛 | 判定标准 |
| --- | --- |
| `G1` 显示 | 6 态各进入/退出 4 次，共 **20 次观测**，每次可目视区分；无花屏/偏移/反色错误；**20/20** |
| `G2` 任务卡 | 连续 20 次状态更新，卡内容 **≤1 s** 上屏（设备日志 + 宿主时间戳）；失败样本不剔除；**≥19/20** |
| `G3` 多卡 | 注入 3 卡 + 第 4 卡，20 次；最新置顶、最旧淘汰、同名更新置顶；**20/20** |
| `G4` 失联 | 停止宿主心跳后 **15–17 s** 进入 OFFLINE，20 次；**≥19/20**；恢复心跳后 5 s 内回到原态 |
| `G5` 番茄钟 | 完成/暂停/放弃/继续各 1 组（短时长构建）+ 重启 1 次；状态与统计不丢；**4/4 + 1/1** |
| `G6` 按键 | 两个应用键（BOOT/PLUS）短按/长按各 20 次，无误触发、无漏触发，**每项 ≥19/20**；`PWR` 长按关机 **5/5**，短按不触发应用动作 **5/5** |
| `G7` 触摸 🔴 | 点卡 / 竖滑翻页 / 长按菜单 / 摸头各 20 次；**每项 ≥19/20**；戴手套/湿手不在承诺范围 |
| `G8` IMU 🔴 | 抬腕唤醒 20 次 **≥19/20**；摇晃动作 20 次 **≥18/20**；静止 10 分钟误触发 **≤1** |
| `G9` 语音播报 | 确认/完成/失败各 20 次；每次恰好一次，不重复不误播；**60/60**；静音后 20 次静默 **20/20** |
| `G10` 语音输入 | 按住说话 20 次；≥300 ms 才上传；30 s 硬停；网络失败有可见错误且不卡死；**20/20** |
| `G11` AEC 🔴 | 播报 8 s 语音时，距设备 30 cm 说"停止"，**20 次中 ≥15 次**在播报结束前被识别；降级路径必须可用 |
| `G12` 事件入口 | 任意本机脚本 POST 一个事件 → 设备 1 s 内显示，20/20；三通道各 20 次；跨通道重复 10 次只处理 1 次 |
| `G13` 配网 | 扫描列表可见 ≥3 个 AP；选网 + 密码 → 60 s 内拿到 IP；错误密码 → 2 分钟内回落热点；各 5 次 |
| `G14` 电池 🔴 | 万用表读数与 UI 电量对比 5 个点，误差 **≤5%**；充电中图标正确；低电阈值触发提示 |
| `G15` OTA 🔴 | 正常升级 5/5；断电中断 5 次均可回滚到旧版本；校验失败拒绝安装 5/5 |
| `G16` 稳定性 | 插电连续 **2 小时**无死机/无看门狗复位/无内存持续下降；电池供电 **1 小时**不掉电重启 |
| `G17` 构建可复现 | 新机器 `git clone` → `idf.py build` 成功；manifest 校验一致；**无手工修补步骤** |

### 4.1 测量口径

- 样本量：每个门槛按上表；**分母包含失败、超时、异常**。
- 分组：冷启动 / 稳定态 / 重连 / 主动取消**分别报告**，不合并。
- 时序：`G2/G4/G12` 用设备日志 + 宿主接收时间戳；视频只作交叉验证。
- P50/P95 是描述统计，**不替代硬门槛**。
- 触摸/IMU/AEC 的"未达标"不得用降低阈值解决，必须报告并请用户重定范围。

## 6. 架构候选（拟定，详见 `03-feasibility.md` §6）

| 方案 | 结论 |
| --- | --- |
| **A：派生 MIT `ESP32-buddy` + 新板级层（推荐）** | 许可干净、复用已验收资产；工作量集中在版式、音频输入、新驱动 |
| B：移植 `vibebuddy` Rust 固件 | **GPL 传染**；总线/触摸/宿主全不匹配；不推荐 |
| C：全新净室重写 | 成本最高，放弃已验收资产；不推荐 |

> 若 A 的关键门槛失败，**重新提交设计选择**，不得自动退到 B。
